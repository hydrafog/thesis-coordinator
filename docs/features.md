# Features

## Roles

- **Students** submit proposals, communicate with supervisors, upload drafts, respond to reviews, and view defense information.
- **Supervisors** manage assigned theses, review drafts, set milestones, communicate privately, and recommend readiness.
- **Committee members** inspect the defense file, record rubric scores, and contribute to final minutes.
- **Faculty administrators** configure periods and deadlines, approve proposals, assign committees, resolve conflicts, and oversee reports.

## Thesis lifecycle

1. A student submits a topic proposal.
2. Faculty administrators filter and route proposals for review.
3. A supervisor accepts or requests changes, and the proposal is approved.
4. The student and supervisor track milestones, drafts, feedback, and similarity checks.
5. The final submission is locked for defense preparation.
6. An administrator assigns a conflict-free defense slot and committee.
7. The committee verifies the defense file and records grades.
8. The system generates the final defense minutes and retains the audit trail.

## Supporting capabilities

The platform should provide Google sign-in with institutional account checks, deadline notifications, private messaging with attachments, versioned PDF and ZIP uploads, chapter annotations, similarity reports, committee conflict checks, a live gradebook, and generated PDF minutes.

All feature mutations should expose clear validation errors and preserve an audit trail. A user's interface may hide unavailable actions, but the server remains the source of truth for permission checks.
